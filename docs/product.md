# OMP Harness² 产品定义

本文件定义产品目标、alpha 范围及发布门槛。它不是已实现功能清单：当前实现情况以代码、测试与运行记录为准。未经真实 OMP 任务验证的能力，不应在用户界面或发布说明中标为可用。

## 产品目标

让 OMP 用户为一个明确、可重放的本地代码任务运行 Harness²：从共同基线实际执行任务，提出通用与领域候选 harness，比较执行证据，组合改进，再交付可审阅的最终产物。跨任务保留有证据支持的改进经验。

产品入口是安装到 OMP 的常驻插件。插件负责命令、进度、取消与结果展示；持久化 controller 负责实验。优化过程不阻塞 OMP 的短生命周期事件处理器，也不直接修改用户当前会话的全局配置。

本轮目标是一个可测试的 alpha 纵向切片，不是生产就绪版本。alpha 成功意味着能完成一次可追溯的本地实验，并在用户显式要求后应用选定结果；不意味着已证明 Harness² 在任意任务上提高质量。

当前实现的基线是固定、受限的 OMP 文件编辑 profile：关闭原生工具与自动发现，由 host 提供文件读取、目录列举和 UTF-8 写入。它不是用户当前的完整 OMP 会话，也不继承个人 skills、环境指令或 OAuth/订阅登录。模型使用明确的 direct API provider/model 和显式 API key。工作区必须是本地 Git 仓库顶层。

首版不能运行 shell、构建、测试、网络工具、MCP 或子代理。产物中的“验证”只能指实际完成的静态检查或代码阅读；模型不能声称已运行测试。对受限 baseline 的改进不能写成对完整原生 OMP 的改进。

## 目标用户与适用任务

适合愿意为较复杂代码任务支付额外计算成本、需要比较执行方案的 OMP 用户。输入应具备以下条件：

- 一个明确的任务描述，以及完成任务所需的本地文件。
- 可冻结、可复制的初始工作区。
- 多次执行不会造成不可逆的外部副作用。
- 有可检查产物，例如补丁、测试结果或生成文件。

alpha 不支持直接重放发送消息、下单、发布、部署、修改远端数据库等操作。涉及这些行为的任务必须先转成只产生本地产物的任务。独立进程和工作区副本不是操作系统沙箱。

## 用户流程

1. **启动。** 用户在 OMP 中显式提交任务。系统记录任务、基线 harness、运行配置、策略、预算及当时可见的经验，分配稳定的 run ID。首次执行阶段开始前冻结实际工作区；排队期间的文件状态不应描述为已冻结。
2. **执行。** 显示当前阶段、已完成的执行、累计可观测用量和失败原因。用户可取消；取消不会应用结果。
3. **审阅。** 展示选定结果、相对初始工作区的差异、选择理由、证据链接和未完成的验证。
4. **应用。** 用户显式触发 apply。系统先验证主工作区未漂移，再应用已经选定的产物。apply 不重新调用模型完成任务。
5. **保留经验。** 反思阶段提出可复用经验，附带证据与适用条件；证据不足时不创建经验条目。经验采纳与工作区 apply 是两个独立、可审计的操作。

命令名称和参数以实际插件注册与 CLI 帮助为准。用户界面应始终区分“实验已完成”“结果已选择”“结果已应用”，不能用一个完成标记替代三种状态。

## Alpha 范围

| 范围 | Alpha 要求 |
| --- | --- |
| 入口 | OMP 插件命令与可测试的 controller 入口 |
| 执行器 | 独立进程中的已安装 OMP，通过 stdio JSONL RPC 通信 |
| 任务 | Git 仓库顶层内、仅需文件检查与修改的可重放代码任务 |
| 算法 | `k=1` 的完整 Propose–Probe–Compose，随后反思 |
| 可编辑面 | prompt append、tool guidance、通过 `harness://skills/` 按需读取的声明式 skills |
| 实验记录 | 任务、配置、阶段、证据、产物、用量和选择结果持久化 |
| 恢复 | 识别已完成阶段与中断阶段；不得将中断伪装为成功 |
| 预算 | 总时间和总费用预算的检查、取消及超限状态；说明计量限制 |
| 采纳 | product 与 research 策略可区分，默认显式人工 apply |
| 经验 | 与任务产物分离的持久化经验库，保存证据和适用范围 |

本表是本轮验收目标。某项尚未通过对应测试或实机验证时，必须在发布状态中列为未验证或未完成。

后续范围包括 `k>1`、并行调度、任意生成脚本或 TypeScript extension、容器隔离、跨项目共享经验及自动应用。这些都不应由 alpha 的接口占位推断为已实现。

当前只继承允许列表中的 API key 环境变量，不复制 OMP 登录数据库或自定义 gateway 配置。若实际用户 home 中存在 `.env`，runner 会拒绝启动，避免 OMP 的自动加载破坏配置隔离；不会读取其内容或自动删除它。

## 两种采纳策略

### research

用于与固定参考实现对照。对于 `k=1`，采用 composed harness 的最终执行结果，不以隐藏评测分数在 baseline 与 composed 之间择优。失败、格式回退和重试行为必须显式记录。

策略名不等于“完整复现论文”。报告还需要注明参考 commit、模型、可编辑组件、提示词、执行器、预算与所有偏离。对未实现的论文细节不能声称复现。

### product

当前实现对已完成的 baseline 与 final 产物进行匿名比较，selector 可以选择 baseline；选择响应格式无效时保留 baseline。composed 执行本身失败会使 run 失败，不能描述成所有失败都会自动回退。任何质量比较都必须展示其可观察证据和不确定性。

这属于工程策略，不与 research 结果混合报告。无论哪种策略，选择候选都不意味着已获得向主工作区写入的授权；默认 apply 仍由用户显式触发。

## 必须成立的不变量

1. **同一起点。** baseline、INV、DOM 和 composed 的任务执行从同一冻结输入开始；前一次执行的修改不能成为下一次执行的初始代码。
2. **控制层不可自改。** 模型不能修改 controller、预算、输入快照、强制权限、评估入口或采纳策略。
3. **候选完整可追溯。** 每个结果都能对应到准确的 harness 内容、配置、工作区指纹和执行证据。
4. **失败不等于证据。** 中断、协议错误、超时与模型成功完成必须分开记录。
5. **一次显式应用。** apply 不再执行任务；重复 apply 不重复产生修改；工作区漂移时拒绝覆盖。
6. **经验不等于答案。** 经验库不自动保存任务答案、凭证或无证据的泛化结论。
7. **没有观察到不等于零。** 缺失费用或 token 数据必须标为未知，不能记作零来通过预算检查。
8. **取消优先于采纳。** 被取消的运行不能继续自动应用产物或发布经验。

## 成本与质量呈现

`k=1` 包含四次任务执行：baseline、INV probe、DOM probe 和 composed rollout；另有两次 proposal、一次 composition，以及反思阶段。一次“执行”通常包含多次模型请求与工具调用，不能把它描述为四次 API 调用。

预算至少区分已观测费用、估算费用和未知费用。controller 的停止只能防止后续工作，并尽力取消正在运行的请求；已经发出的远端请求可能继续计费。alpha 不承诺服务商账单层面的精确费用硬上限。

对外评估首先比较相同受限 profile 下的一次执行、等预算重复执行加选择、Harness²，以及关闭跨任务经验的 Harness²。完整原生 OMP 可作为另一个参照，但必须单列工具和配置差异，不能将额外工具权限的影响归因于 Harness²。比较使用相同任务输入、模型配置和明确的预算口径。隐藏评测在采纳后进行，不能反向进入同一任务的优化流程。

## 验证范围的表述

| 验证层 | 能支持的结论 | 不能支持的结论 |
| --- | --- | --- |
| TypeScript 与默认单元测试 | 类型、controller 状态机、假 runner/假 RPC 下的协议与文件契约 | 真实 OMP 与服务商传输可用 |
| `doctor` 的本地 OMP 检查 | 指定 OMP 的版本、RPC 能力和 host-only 工具边界 | 已成功发送模型请求或完成代码任务 |
| `RUN_REAL_OMP_TEST=1` 的本地集成测试 | 真实 OMP agent loop/RPC 与固定模拟 provider 的文件调用、usage/settled 联动 | 真实远端 HTTP、API key 认证、模型质量或论文性能 |
| 真实 direct API smoke run | 指定版本、provider、模型下的实际请求与完整任务行为 | 所有 provider 兼容或 Harness² 普遍改善质量 |

实际通过情况以该次测试输出为准。测试脚本已经存在、默认跳过或使用模拟 provider，都不能表述为真实远端推理验证已完成。

## 发布门槛

### 可测试 alpha

- 能用确定性假 runner 跑完整阶段链，并校验四个 solver 的初始输入相同。
- 能区分成功、失败、取消、预算耗尽及中断恢复。
- 能验证 product/research 的差别，且默认不写入用户工作区。
- apply 能检测工作区漂移、拒绝越界产物，并具备重复调用测试。
- 状态、证据、候选与经验引用之间不存在断链。
- 验证报告分开列出默认测试、doctor、本地真实 OMP 加模拟 provider，以及真实 direct API smoke run；未执行的层级明确标注，不能合称“真实 OMP 全流程已验证”。

### 面向日常使用的版本

- 在真实 OMP 的错误、超时、取消、后台任务和重启场景下完成回归验证。
- 验证 controller 遭 `SIGKILL` 后活动 worker 的发现与回收，避免 resume 和遗留执行同时继续。
- 明确支持的 OMP/Bun/平台版本，并验证 RPC 兼容性。
- 在联网 CI 中完成正常依赖安装、锁文件和真实 direct API 的认证/传输/用量集成检查。
- 对工作区复制、权限边界、路径逃逸、符号链接和外部状态进行审查。
- 用等预算基线评估收益、成本、失败率及回退率。
- 验证长期经验不会持续积累无效规则，且用户可以检查、禁用和删除经验。

产品不能因为模块名、接口或测试用例已经存在，就宣称上述门槛全部满足。
